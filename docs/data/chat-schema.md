# Chat schema (KEL-119, KEL-120, KEL-154)

Chat data resides in a service-owned PostgreSQL database, installed by `kelolakelas-chat-service/migrations/000001_chat.up.sql`. Cross-service user, member and tenant UUIDs are application references, not foreign keys into identity.

- `conversations`: UUID primary key; required `tenant_id`, `kind` constrained to `staff|schedule_request|report` plus `notification` since KEL-154, `subject_id` (member UUID for staff, academic subject UUID for context rows, parent UUID for notification rows), creator UUID and timestamps. Migration `000002_context_chat.up.sql` requires `member_user_id` only on staff rows and `parent_user_id` only on context rows; migration `000003_notification.up.sql` adds the notification kind with `subject_id = parent_user_id` enforced by `conversations_participants_check`. `context` defaults to `{}` and holds immutable display snapshots for context rows (notification rows carry `{}`). Unique `(tenant_id, kind, subject_id)` prevents duplicate creation, including concurrent attempts. Tenant/recent-order and partial parent/recent-order indexes support listing.
- `messages`: UUID primary key, conversation foreign key with cascade delete, sender UUID (nullable since KEL-154; NULL for system rows), `sender_kind` constrained to `parent|member` plus `system` since KEL-154 (`messages_sender_shape_check` keeps system rows NULL-only and parent/member rows non-NULL), plain-text `body` length 1–2000 database characters, nonempty `client_message_id`, timestamp. Unique `(conversation_id, sender_user_id, client_message_id)` handles retries for user rows; the partial index `messages_system_idempotency` on `(conversation_id, client_message_id) WHERE sender_kind='system'` handles idempotency for system rows. `(conversation_id, created_at DESC, id DESC)` supports timeline pagination. KEL-120 writes `sender_kind=parent` for parent messages on context conversations; staff messages remain member messages. KEL-154 writes `sender_kind=system` for internal notification messages.
- `conversation_reads`: `(conversation_id, user_id)` primary key, cascade conversation foreign key, monotonically updated `last_read_at`. Unread counts exclude messages by that user and messages at or before the watermark; since KEL-154 the exclusion uses `IS DISTINCT FROM` so system rows (NULL sender) count toward the parent's unread.

Apply migrations `000001` then `000002` then `000003` before starting the server. `000002_context_chat.down.sql` refuses to remove the new kinds while any context conversation exists; `000003_notification.down.sql` refuses while any notification data exists; `000001_chat.down.sql` removes the tables and is destructive.
