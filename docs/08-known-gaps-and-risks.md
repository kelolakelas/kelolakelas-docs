# Known gaps and risks

Severity is an engineering assessment, not an exploit claim. “Confirmed” indicates direct code evidence; recommendations are not current behavior.

| Finding | Severity | Component | Evidence | Impact | Status / recommended remediation |
|---|---|---|---|---|---|
| Gateway rate limiter deliberately fails open when Redis unavailable/errors | Medium | gateway | `cmd/server/main.go:35-39`; `rate_limit_middleware.go:75-79,90-95` | abuse protection is absent during Redis outages | Confirmed. Choose explicit fail-closed/degraded policy and monitor Redis health. |
| gRPC identity service binds `:50051` and inspected client/server show no transport/auth configuration | High | identity/academic | identity `cmd/server/main.go:135-151`; academic `pkg/grpcclient/{tenant_client,permission_client}.go` | tenant and permission interfaces can be exposed/intercepted on an untrusted network | Confirmed. Restrict network, use mTLS and service authentication. |
| Many route groups still require only a JWT; catalog mutation permission enforcement is not universal across all academic domains | High | identity/academic/billing/gateway | service route blocks and gateway router; academic catalog routes use `permission_middleware.go` | authenticated roles may still reach operations outside the implemented catalog/schedule mapping | Confirmed residual gap; extend authorization per domain in a separately scoped task. |
| Web proxy performs only an optimistic JWT shape/expiry check, not signature validation | Medium | web | `kelolakelas-web/proxy.ts`; identity `pkg/jwt/jwt.go` remains the validation authority | a forged but structurally valid cookie can still change the initial navigation decision; backend rejects it on protected API calls | Confirmed. Malformed/expired cookies are cleared and redirected to login; cryptographic validation remains a follow-up. |
| Academic activation can remain unavailable until the durable retry limit is reached | Medium | billing/academic | billing `payment_reconciliations`, `reconciliation_worker.go`; academic `ActivateEnrollment` | paid transaction may remain `reconciling` or `terminal_failed` and needs operator follow-up | Confirmed residual risk. Automatic retry and observable state are implemented; refund automation and renewal reconciliation remain out of scope. |
| Seats held by transactions that failed or expired before KEL-26 are not released | Medium | billing/academic | `migrations/20260921000000_reconciliation_kind.up.sql` adds `kind` with `DEFAULT 'activation'` and no backfill; `internal/repository/transaction_repository.go` enqueues releases only for transactions it expires itself | pre-existing `failed`/`expired` transactions keep occupying `pending` enrollments and their seats stay unavailable to other parents | Confirmed by omission, deliberate. A backfill was rejected because billing cannot distinguish a hold that is still legitimate from one that was abandoned, so deploying the feature would silently drop seats. Remediation is an explicit, reviewed data operation (see [ADR 0011](adr/0011-release-enrollment-seat-on-failed-payment.md)). |
| Seat release depends on the reconciliation worker, which has no leader election | Medium | billing | `internal/usecase/reconciliation_worker.go`; `internal/repository/payment_reconciliation_repository.go` `ClaimDue` uses `FOR UPDATE SKIP LOCKED` with a five-minute lease | a release job could be claimed again after its lease expires and the Academic call could be issued twice; harmless because the release endpoint is idempotent, but attempts are consumed | Confirmed residual risk, mitigated by idempotent release rather than by coordination. Same underlying gap as the entry below. |
| In-process background workers have no leader election or distributed lock found | Medium | billing | billing main `:107-115`; `subscription_worker.go`; `reconciliation_worker.go`; `transaction_expiry_worker.go` | multiple replicas could process the same due work | Inferred from code. Introduce singleton scheduling/locking and execution telemetry. The expiry worker's row claim is idempotent (see ADR 0009), but the renewal and reconciliation workers are not guarded. |
| Health checks report process status only | Low | all Go services | gateway router, each `cmd/server/health.go` | orchestrator may mark services healthy while dependencies are unavailable | Confirmed. Add readiness dependency checks and separate liveness/readiness. |
| No metrics/tracing, deployment/IaC/CI, or verified backup/runbook assets found | Medium | workspace | repository inventory/search | operational diagnosis and recovery cannot be established from code | Not found. Add controlled operational artifacts and observability. |
| Stale `Tutorin` naming and generated copied Swagger coexist with KelolaKelas code | Low | web/docs | web `package.json`, layouts, `_docs/api/*`; service Swagger | operator/client confusion and stale contracts | Confirmed. Regenerate docs from current services and complete branding migration. |

Additional observations: service CORS only exists at the gateway; direct service exposure must be controlled by deployment (currently **Unknown**). Default DB SSL mode is `disable`, appropriate only for trusted local connections. No refresh/logout/password-reset/MFA endpoints were found.

**Resolved since the 2026-09-15 snapshot:** the academic category, class, list, and schedule handlers previously accepted `X-Tenant-ID` as a tenant source. Because the gateway only overwrites that header when the token carries a tenant claim, a parent token (which legitimately has none) could name an arbitrary tenant. Tenant context is now derived from the verified JWT claim only, with 403 for a missing claim, 401 for an unusable claim, and a claim/path match requirement on tenant enrollment; `kelolakelas-academic-service` commit `7e1ade30858af0d365f61e0f13526c9a4c602d60` (PR #5, KEL-19). See [ADR 0010](adr/0010-tenant-context-from-verified-jwt-claim-only.md). Billing was checked and never trusted the header; its handlers already read the JWT context value (`kelolakelas-billing-service/internal/delivery/http/handler/transaction_handler.go:33,109`).

**Also resolved:** an unpaid enrollment previously held its schedule seat indefinitely, because the academic capacity predicate counts `status IN ('pending','active')` and nothing moved an abandoned `pending` enrollment out of that set. Expiry and failure now enqueue a durable `release` reconciliation that drops the pending enrollment, so the seat returns to the catalog. `kelolakelas-billing-service` commit `ca5698b` (PR #5) and `kelolakelas-academic-service` commit `defd477` (PR #6), KEL-26. See [ADR 0011](adr/0011-release-enrollment-seat-on-failed-payment.md). The caveat about pre-existing rows is recorded above.
