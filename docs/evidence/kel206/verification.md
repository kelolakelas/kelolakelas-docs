# KEL-206 class deletion consistency verification

Date: 2026-10-17 (Asia/Jakarta).

**Observed diagnosis:** the reported stale schedule after class deletion did not reproduce on refreshed main: web `1ca7ecb7059e8a8738d1655522875e98b0a11d3c`, academic `e07e4a930e8a9fda0f5c187afabe200a56583845`, gateway `622e61d835e815a40f3e8778a599f908c9273f11`. The gateway executable's embedded VCS revision matches that main and reports `vcs.modified=false`. Existing `DeleteClass` runs schedule soft deletion, future-session cancellation and class soft deletion in one transaction; schedule listing filters both deleted schedules and deleted parents. The web DELETE action already revalidates the classes route, which refreshes both tabs. No new production-code fix or confirmed original runtime cause is claimed.

**Delivered:** academic revision `102685b` adds real-PostgreSQL lifecycle regression and an opt-in isolated browser fixture. These test actual JWT/permission middleware, handlers, use cases and repositories; identity permission/session replies remain controlled test doubles. Each run creates and drops its own schema and uses a schema-only search path. The lifecycle regression is enabled in the existing required GitHub `gate` through its `KEL196_TEST_DSN` configuration. The browser fixture is opt-in via `KEL206_STACK_CONFIG` and `KEL196_GATEWAY_BINARY`; it exports synthetic configuration with mode 0600 and removes it at shutdown. The repository's current-schema initializer supplies fixture tables; no migration changed.

**Automated acceptance:** `TestClassDeletionPostgres` passed under the race detector in 18.76 seconds, including four subtests: successful cascade with page-one/page-two/search reads and accurate surviving-row counts; active-enrollment 409 and foreign-tenant 403 without writes; injected failure at the final class write rolling back schedules and future-session cancellation; and concurrent DELETEs producing a consistent final state. It also checks repeated deletion, completed/past session retention and cancellation only of future scheduled sessions. Queries assert that soft-deleted history rows still exist.

**Browser acceptance:** actual Next.js dev UI → Server Action → unchanged gateway → real academic handler/use case/repositories → disposable PostgreSQL. Two synthetic group classes each had a schedule. [Confirmation](before.png) named the target; confirm returned success, and the current Classes view immediately retained only the control class ([after](classes-after.png)). The [Schedules tab](schedules.png) immediately showed one schedule for the control class. [Reload](reload.png) kept those counts. The [360px mobile view](mobile.png) had no horizontal overflow and did not show the deleted target. Database readback confirmed target class/schedule `deleted_at` values, one unchanged control class, a retained past scheduled session and a cancelled future scheduled session. Browser errors were empty. No production data, live identity, payment or email-provider acceptance is claimed.

**Local checks:** gofmt, `go mod verify`, `go vet ./...`, `go test -race -count=1 ./...`, `go build ./...` and diff whitespace checks passed. The separate PostgreSQL race regression ran with an isolated schema. The first non-escalated Go suite hit loopback-port sandbox restrictions; the full suite then passed with required local networking permissions. Thirty existing web deletion/action/list tests passed. No web source changed; its production build was already verified by the KEL-205 main CI at the same web revision.

**Scope and remaining uncertainty:** the original reported environment's deployed revision/request/cache state was not available, so its original cause remains unknown. This change locks the acceptance behavior proven on current main; it does not claim to repair an unobserved deployment. If the report recurs, capture deployed SHAs, DELETE response/request reference, both listing responses and persisted soft-delete state before changing behavior. No new ADR is required because architecture, API contracts and deletion policy remain unchanged.
