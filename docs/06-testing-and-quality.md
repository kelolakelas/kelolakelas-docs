# Testing and quality

**Implemented:** Go unit tests exist for config, middleware, selected handlers/use cases, database utilities, migration tooling, Duitku signatures, email client, and subscription worker. Web exposes Vitest through `npm run test`, plus `eslint`, TypeScript checking, and production build commands. Auth-routing and proxy regression tests cover role-aware destinations, open-redirect rejection, and malformed/expired cookie handling. Pure presentation and parsing helpers are unit-tested without a DOM: `lib/list-envelope.test.ts` covers the enveloped, bare-array and malformed payload shapes the tenant class readers accept, and `lib/class-publication.test.ts` covers the publication/enrollment badge and action labels. The web CI gate in `.github/workflows/ci.yml` runs on every pull request to `main` and executes `npm ci`, `npm run test`, `npx tsc --noEmit`, ESLint over the TypeScript files changed by the pull request, and `npm run build` with a placeholder `GATEWAY_API_URL`; the Go repositories run `go mod download`, `go mod verify`, a `gofmt` check, `go vet ./...`, `go test -race -count=1 ./...`, and `go build ./...`. Evidence: `rg --files` under each repository and `package.json`, `lib/auth-routing.test.ts`, `lib/list-envelope.test.ts`, `lib/class-publication.test.ts`, `proxy.test.ts`, `.github/workflows/ci.yml`.

No tests were run for this documentation snapshot: doing so may compile with the host Go version and could require module/cache changes; no end-to-end configuration or external-service sandbox was authorized. Static checks performed are recorded in the root README and evidence index.

Swagger JSON/YAML is generated and present for all three services. Treat it as a secondary contract: it can lag route/handler changes, as indicated by stale `Tutorin` copies under web `_docs/api`.
