# Chat service

**Implemented (KEL-119):** `kelolakelas-chat-service` runs a Go `net/http` server (`cmd/server/main.go`) with `/health` and staff-only conversation routes. It uses its own PostgreSQL database (`migrations/000001_chat.up.sql`) and a tenant/member-scoped identity gRPC `CheckPermission` request for `chat:manage` (`pkg/grpcclient/permission.go`). Configure the same JWT HMAC secret used by identity, a PostgreSQL connection and `IDENTITY_GRPC_HOST`; run the migration with `cmd/migrate` before starting the server.

`internal/chat/chat.go` is the visibility boundary. A non-parent owner sees a staff conversation when its `member_user_id` matches their verified JWT `user_id`; another tenant member sees it only when identity grants `chat:manage` for the claimed tenant, role and member. Permission failure denies access. Detail, messages, send and read return 404 for invisible conversations. Listing filters in SQL before pagination and validates returned rows. Creation accepts only `staff` and is unique per `(tenant_id, kind, subject_id)`; the subject is the caller's member ID. HTTP errors do not return underlying database details.

Messages contain plain text only, 1–2000 Unicode code points after trimming, with a required `client_message_id`. The database unique key `(conversation_id, sender_user_id, client_message_id)` makes retries return the existing message. Unread count excludes the reader's messages and uses `conversation_reads.last_read_at`; `/read` advances that watermark. Message timelines are ordered newest first by `(created_at, id)`.

**Implemented (KEL-120):** Migration `000002_context_chat.up.sql` adds `schedule_request` and `report` kinds with a required parent for those rows; staff rows retain a required member. On creation, `pkg/academic/client.go` retrieves context over credential-protected internal HTTP, while `pkg/grpcclient/tenant.go` retrieves the public tenant name. The service compares academic `parent_id` or `tenant_id` to verified claims and checks `chat:manage` for schedule members or `report:read` for report members. It stores the parent, tenant and display snapshot once; later reads use stored values, including after academic becomes unavailable or the subject changes. Parent listing spans tenant IDs; member listing filters permissions in SQL before pagination and detail/send/read share the service's visibility check. Context creation fails closed with sanitized 503 on academic failure; missing subjects and unauthorized visibility return 404. The rollback migration rejects removal when context conversations remain. **Integration boundary:** as of KEL-119 the existing API gateway and web app do not route or render this service. Direct service HTTP requires a valid Bearer JWT. Attachment and notification remain unimplemented; realtime transport is implemented since KEL-121 (ticket-based WebSocket, single instance). Tests include service and handler authorization coverage and an optional PostgreSQL integration test gated on `TEST_DATABASE_URL`; the implementer executed it locally, while CI runs without that variable. Evidence: [chat-service PR #1](https://github.com/kelolakelas/kelolakelas-chat-service/pull/1), squash `b434adaf2ba849d6202d6c69e36337ea623305cb` and [post-merge gate](https://github.com/kelolakelas/kelolakelas-chat-service/actions/runs/36431769995).

**Implemented (KEL-121):** ticket-based realtime WebSocket (`internal/chat/wsticket.go`, `internal/chat/wshub.go`, `internal/delivery/http/ws.go`). `POST /api/v1/chat/ws-tickets` behind JWT mints a single-use ticket (>=32 random bytes, SHA-256 hash at rest, 60 s TTL, bound to actor claims and token `exp`); `GET /api/v1/chat/ws?ticket=` upgrades only on atomic consume, otherwise 401 with no upgrade. `Service.Send`/`Read` fan out `message.created`/`conversation.read` through the in-memory hub, filtered by the same visibility boundary as REST with `chat:manage`/`report:read` frozen at connect time (`Service.Rights`). Liveness is 30 s ping with close after two missed pongs, close at token expiry or 30-minute lifetime, 4 KB client frame cap, 5 connections per user, slow-consumer eviction, and normal-close on shutdown. The WebSocket library is `gorilla/websocket` v1.5.3; see [ADR 0047](../adr/0047-ticket-based-chat-websocket-auth.md).
