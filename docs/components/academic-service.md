# Academic service (`kelolakelas-academic-service`)

**Implemented:** Gin HTTP server default `:8081`, GORM/PostgreSQL store and public catalog routes. Protected HTTP routes cover categories, classes (including tenant-scoped attribute update behind `class:update`), schedules/sessions, students, attendance, reports and enrollment queries. The service dials identity gRPC using `IDENTITY_GRPC_HOST`; use cases validate tenant status before category/class operations (`pkg/grpcclient/tenant_client.go`, `internal/usecase/category_usecase.go:77`, `class_creation_usecase.go:48`). Tenant-scoped handlers resolve the tenant from the verified JWT claim through `tenantIDFromContext`, never from a request header: a missing claim is 403 and an unusable claim is 401 (`internal/delivery/http/handler/tenant_context.go`). Session and schedule mutations carry that tenant into the query rather than checking it afterwards: the five operations (reschedule, permanent schedule change, temporary and permanent tutor change, attendees) resolve the target through `GetByIDForTenant`, which joins `classes` and filters on the owning class's tenant, so a foreign resource is 404 with no data change; the three bulk session writes repeat the predicate as `class_id IN (SELECT id FROM classes WHERE tenant_id = ?)` (KEL-17, [ADR 0019](../adr/0019-tenant-scoped-session-and-schedule-mutations.md)). Catalog mutation routes additionally call identity's `tenant.PermissionService/CheckPermission` middleware, which reads persisted role permissions for the caller's `role_id` **inside the tenant the caller is operating on**; academic sends the tenant from the same verified JWT claim the rest of the request uses, and a caller without a usable tenant claim is refused before identity is consulted. Because identity only accepts a role that belongs to that tenant or is a system role, a role lifted from another tenant cannot authorize these mutations. Denied or missing role context is 403 and identity failure, including a check slower than `IDENTITY_PERMISSION_TIMEOUT_MS` (KEL-78), is 503 (`pkg/grpcclient/permission_client.go`, `internal/delivery/http/middleware/permission_middleware.go`). The same middleware guards the tenant-side student and enrollment operations — `student:read` for list/detail, `student:create|update|delete` for the mutations, `enrollment:create` for `POST /tenants/:tenant_id/enrollments`, and `enrollment:read` for enrollment list/detail — while parent tokens skip the check because they carry ownership rather than a role, leaving the handler's own owned-resource rules as the only authority for them (KEL-21). Since KEL-135 the three session read routes (`GET /sessions`, `GET /sessions/:id`, `GET /sessions/:id/attendees`) require `schedule:read` for tenant members through `RequirePermissionForTenantResource` with the same parent-token skip (below). Its catalog use case obtains public tenant information via gRPC. It also makes an internal HTTP payment-initiation call to billing when marketplace catalog enrollment needs payment (`pkg/billing/client.go:45-75`, `internal/usecase/enrollment_usecase.go`).

Academic migrations own categories, classes, schedules, sessions, students, enrollments, attendance, student notes, reports and tenant-location snapshots. They use soft-delete columns where supplied; many identity IDs are UUID values without cross-database foreign keys.

Catalog and schedule mutation routes apply the persisted role-permission check described above before invoking handlers. Other academic domains still rely on JWT authentication plus their existing handler/use-case checks; individual evidence should be reviewed before granting a role access. See [academic API](../api/academic.md).

## Catalog tenant snapshots and outage behavior

**Implemented (tenant snapshots):** the public catalog does not contact identity for tenant snapshot data on every request. KEL-98 separately revalidates open catalog policy with identity on every request. `catalogUsecase.refreshTenantSnapshots` lists the tenants that own classes, subtracts the tenants whose `tenant_location_snapshots.updated_at` is younger than `CATALOG_TENANT_INFO_TTL_MINUTES` (default 5), and only refreshes the remainder — so a request inside the TTL performs no gRPC call and no stored-procedure write. The refresh is written with a single `ON CONFLICT (tenant_id) DO UPDATE` that touches only the refreshed rows, which keeps the snapshot age the TTL is measured against. When identity is unreachable the refresh is logged at `WARN` and skipped, and the catalog still answers from the stored snapshot; a tenant id identity returns that is not a UUID is dropped rather than stored under `uuid.Nil`. Identity calls issued by the catalog are bounded per call by `CATALOG_TENANT_INFO_TIMEOUT_MS` (default 2000) in `pkg/grpcclient/tenant_client.go:41-68` (KEL-42).

The same change made tenant visibility consistent between the two catalog paths: both `List` and `GetByID` join `tenant_location_snapshots` with an inner join on `is_active = true` (`internal/repository/catalog_repository.go:49-52,92`), so a class belonging to an inactive or not-yet-snapshotted tenant is absent from the list and also not reachable by direct id. Filtering, sorting, pagination, and per-schedule availability are unchanged. Evidence: `internal/usecase/catalog_usecase.go`, `internal/repository/catalog_repository.go`, `pkg/grpcclient/tenant_client.go`.

## Billing-driven enrollment transitions

**Implemented:** billing confirms paid seats and releases unpaid ones through internal-credential routes. `PUT /internal/enrollments/:id/activate` confirms a paid seat. `PUT /internal/enrollments/:id/release` (KEL-26) moves a `pending` enrollment to `dropped` so its schedule seat is available again. Release is idempotent — repeating it succeeds without a second transition — and it never revokes an `active` enrollment, so a late failure notification cannot take back a seat that a confirmed payment already activated. A status that is neither `pending`, `dropped`, nor `active` is rejected with 409 and recorded by billing in the reconciliation row, which makes "paid after the seat was released" an operator-visible outcome instead of a silent success. Evidence: `internal/usecase/enrollment_usecase.go`, `internal/delivery/http/handler/enrollment_handler.go`, `internal/repository/enrollment_repository.go`.

**Implemented (KEL-149):** billing additionally parks, restores, and ends active enrollments through `PUT /internal/enrollments/:id/suspend` (`active` → `suspended`), `PUT /internal/enrollments/:id/resume` (`suspended` → `active`), and `PUT /internal/enrollments/:id/end` (`active`|`suspended` → `dropped`). A suspended enrollment holds no seat, so suspend frees the schedule slot while the row and its history stay; the student is not an upcoming-session attendee and attendance cannot be recorded for it. Resume reclaims the seat under the enrollment row lock and the schedule lock with the same capacity and duplicate checks a new signup passes — a full or ended schedule, or a student who re-enrolled meanwhile, answers 409 and the enrollment stays suspended for billing to retry. End frees the seat permanently through the same `dropped` state the release path writes, so the student may enroll again; a `pending` enrollment is refused because it must go through the cancel/release paths that also unwind billing. All three transitions are idempotent. See [ADR 0050](../adr/0050-enrollment-suspend-resume-end.md). Evidence: `internal/usecase/enrollment_usecase.go` (`SuspendEnrollment`, `ResumeEnrollment`, `EndEnrollment`), `internal/repository/enrollment_repository.go` (`ResumeUnderCapacity`), `internal/delivery/http/handler/enrollment_handler.go`; academic PR [#41](https://github.com/kelolakelas/kelolakelas-academic-service/pull/41), squash `4afb40acde884a2c61639c304c5cb5d9fdbb0fb4`.

## Input bounds and literal search

**Implemented (KEL-87):** list handlers cap `page` at 1000, `page_size` at 100 and `search` at 255 characters, request DTOs cap `varchar(255)` fields at 255 characters and schedule `capacity` at 2147483647, and oversized input answers 400 before any query runs. Every repository `ILIKE` escapes `\`, `%` and `_` through `escapeLikePattern` with `ESCAPE '\'`, so search is literal. Contract details: [Academic API](../api/academic.md#input-bounds-and-literal-search-kel-87). Evidence: `internal/domain/validation.go`, `internal/repository/search.go`; PR [#30](https://github.com/kelolakelas/kelolakelas-academic-service/pull/30), squash `4e63449a66251dfd05d592b6c0805d3c1b1146cd`.

**Implemented (KEL-132):** tenant schedule creation now rejects a private-class item whose capacity is not exactly 1 with HTTP 400 before any write, while group items keep the full valid range and the existing private-request approval path (which always writes capacity 1) is unchanged. Historic private rows with capacity above 1 stay readable without migration. Evidence: academic schedule usecase ErrPrivateScheduleCapacity plus the handler error mapping; unit, PostgreSQL integration, and handler mapping tests; academic PR #40, squash 1a90621237e355cbed0bc1a5e18474a1b0232e49. See academic API input bounds.

**Implemented (KEL-135):** session reads, the own-session filter, substitute-tutor validation, and report update/delete tutor assignment are all permission- and tenant-guarded now. `GET /sessions`, `GET /sessions/:id`, and `GET /sessions/:id/attendees` require `schedule:read` for tenant-member tokens (`RequirePermissionForTenantResource`; parent tokens keep their handler-only path), and `mine=true` on the session list derives `tutor_id` from the verified JWT `member_id` claim while ignoring a client-supplied `tutor_id`. `ChangeTutorTemporary` resolves the session tenant-scoped first (unknown/foreign session stays 404 without a membership probe), then requires identity `tenant.MembershipService/CheckActiveMembership` to answer `active: true` for the requested tutor in the session's tenant before any write: an ineligible tutor (another tenant's member, inactive/removed, or a random id) is 400 `ErrSubstituteTutorNotEligible` with zero writes, and an unreachable, slow, malformed, or unwired check is 503 `ErrSubstituteTutorUnavailable` — fail-closed, never a silent pass (new `pkg/grpcclient/membership_client.go` with `ParseActiveMember` strict verdict and a per-call `IDENTITY_PERMISSION_TIMEOUT_MS` deadline). Report `Update`/`Delete` take the caller's member id and apply the same `IsTutorForEnrollment` assigned-tutor rule as `Create` (403 `ErrReportForbidden`, zero writes). Contract details and error mapping: [Academic API](../api/academic.md#session-read-permission-own-session-filter-and-substitute-tutor-validation-kel-135); design: [ADR 0051](../adr/0051-substitute-tutor-active-membership-gate.md). Evidence: `cmd/server/routes.go`, `internal/delivery/http/handler/{session,schedule,report}_handler.go`, `internal/usecase/{schedule,report}_usecase.go`, `pkg/grpcclient/membership_client.go`; tests `internal/delivery/http/handler/session_mine_filter_test.go`, `internal/usecase/substitute_tutor_membership_test.go`, `internal/usecase/report_permission_test.go`, `pkg/grpcclient/membership_client_test.go`, `cmd/server/attendance_report_routes_test.go`, `cmd/server/swagger_contract_test.go`; academic PR [#42](https://github.com/kelolakelas/kelolakelas-academic-service/pull/42), squash `f77f3f9e8d620b723f041c9838230a1c3d3af5bc`; identity side PR [#35](https://github.com/kelolakelas/kelolakelas-identity-service/pull/35), squash `e094e32fd32e9d950c25dd23efcd52bd03bc5c1d`.
